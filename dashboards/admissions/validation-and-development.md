# Admissions Dashboard — Validation and Development

This page records the iterative development and quality-assurance approach used for the Admissions Dashboard.

## Iterative development

The dashboard was refined through repeated review cycles rather than built as a one-off visualisation. Development notes show recurring feedback on:

- filter behaviour and selection rules;
- naming and tooltip clarity;
- information-panel content;
- chart and table layout;
- comparator presentation;
- measure definitions;
- dashboard navigation;
- data-source refreshes;
- numerical checks against source outputs.

The case study will use this history to demonstrate how feedback was translated into practical reporting improvements without attributing colleagues' work as my own.

## Validation approach

Quality checks included comparison of dashboard figures with the prepared analytical outputs, testing filters and parameters across multiple combinations, checking the Scotland comparator, reviewing dashboard navigation and confirming that displayed measures remained aligned with the selected time window and trend measure.

## Development evidence

The screenshot folders provide technical evidence of the finished Tableau implementation, including:

- ten approved Scotland-level dashboard states across all five time windows;
- seven component worksheets;
- both dashboard parameters;
- nineteen calculated fields organised into logical families.

## Governance boundary

The public portfolio intentionally avoids publishing restricted operational code, source datasets or non-public granular outputs. The evidence is designed to show the breadth of the solution while remaining within the agreed public-use boundary.
